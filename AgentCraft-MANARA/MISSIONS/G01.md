## Objective
Design tables and full rich capability cards; multilingual keywords, positive/negative task samples, source/connector/engine differences; tag and optional pgvector lookup; usage and relationship graph.

## Execution contract
- Confirm input baseline SHA, last approved mission handoff, relevant standard/contract, and runtime resource facts.
- Implement a narrow vertical slice in app repo only; place all mission reports in info repo under `AgentCraft-MANARA`.
- Reuse existing reviewed code/toolkit *read-only*. Version all schemas and migrations. Secure generated or untrusted data paths.
- Run unit, contract and end-to-end tests appropriate to this group. Label mock, permitted live provider call and staging separately.
- Maintain an evidence ledger and include exact commands/results, commits, defects, recovery steps and next mission.

## Acceptance focus
Given prosthetics query, searches show correct engines with reasons and no phantom registry entries.

## Explicit negative requirements
No fabricated data or source access, no public tokens, no silent core rewrites, no product-ready claim without runnable proof, no expanding scope into arbitrary external frameworks. Always retain approved architectural invariant and report blockers.

## Deliverable
Report using `05_ACCEPTANCE/02_MISSION_REPORT_TEMPLATE.md`; code committed to `mayakilzy/AgentCraft-MANARA`; documentation to `mayakilzy/repo-info/AgentCraft-MANARA`. When unclear, prefer a small proven feature over broad unfinished scaffolding.
