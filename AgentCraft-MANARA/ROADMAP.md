## Guiding sequence
**Foundation → contract/registry → first real scholarly connector and research question → evidence snapshot → mold building → on-demand agents → forecasting → professional output → broader clients/media.** This is logical workstream order, not a promise to defer real E2E validation until final phase.

## Groups
- G00 Engineering foundation, standards review, clean repo, interfaces, minimal running API/UI with mock clearly labeled.
- G01 Registry: rich contracts, search retrieval, classification/relationships, snapshots and tests.
- G02 Foundry: source discovery, adapter reuse, sandbox generator/validator, initial real data, approval protocol.
- G03 Evidence and cumulative memory: claims, provenance, time, dedup, reuse, contradictory evidence, tenant isolation.
- G04 Mold Architect: unknown-domain detector, gap analysis, temporary mold composer, registered recipes.
- G05 On-demand agent factory: role resolver, expert blueprint, recipe persistence/rehydration/evaluations.
- G06 Forecasting: policy, time-series baseline, scenario/no-evidence route, backtesting/no leakage and immutable predictions.
- G07 Outputs: dossiers, cue sheet and evidence-linked visual briefing prototype; film workflow design without forced generation yet.
- G08 UX/API integration: full user investigation flow in Arabic/English, admin approval/registry browsers, exports.
- G09 Real cross-domain pilots, adversarial security/legal/temporal evaluations, deployment handoff and recovery.

## Milestone strategy
Each group must add a **demonstrably functional vertical slice**; G02 must include a real source call and evidence, G04 a real unfamiliar-domain mold build, G06 measured benchmark, G08 user-driven E2E. Do not let the project turn into thousands of unused files; refactor down where possible. Maintain small change sets with tests and SHAs; adapt group boundaries if measured results justify without breaking approved architecture.
