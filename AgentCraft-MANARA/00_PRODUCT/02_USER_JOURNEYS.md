## Primary canonical sequence
User requests future of waste recycling / smart prosthetics / EV batteries. System identifies scope/time/place/output. Search mold registry. **If missing, do not pretend mold exists**: inspect Registry for partial existing capabilities; compare missing coverage; Search Foundry discovers sources, selects adapters and creates missing search capabilities in sandbox; validate source rights and connector results; compose **temporary investigation mold**; select general/specialist agent; research evidence, identify data limitations; run appropriate verified methods; publish report with traceable citations; promote reusable engines and recipes, archive investigation. User sees honest progress/state.

## Routes
- A existing mature mold: run with fresh evidence and version pinning.
- B partial capabilities: compose new temporary mold from components without new code where feasible.
- C missing source access: discover source + documented endpoint, generate minimal adapter only if necessary; if unavailable, investigate with clear gap report or human access request.
- D weak forecast evidence: scenario/conditional assessment, no fabricated likelihood.
- E repeated demand: candidate promotion from temporary recipe to maintained version; owner approves maintenance commitment.

## Canonical UX walkthrough: prosthetics
Request: `Evaluate future intelligent prostheses and neural interfaces through 2035, worldwide; distinguish research, regulation, adoption and affordability.`
1. Classify topic as new unless actual registry shows otherwise (do not assume).
2. Search for reusable academic search, patent intelligence, clinical trials, regulation, materials/robotics or cost series; compute coverage gaps.
3. Discover verified primary sources for neural interfaces, prosthetic approvals, prices and trials. Mark marketing releases as announcements, not efficacy evidence.
4. Candidate agents: general research analyst first; transient clinical/regulatory reviewer only if a specialist skill materially improves quality.
5. Analyze maturity ladders: proof of concept → clinical evidence → approval → scaled production → adoption.
6. Forecast conditional technology pathways and adoption with observable leading indicators; confidence based on testable evidence.
7. Deliver citations, evidence ledger, counterevidence, hypotheses, dated forecast scenarios and visual assets with rights.
8. Registry stores reusable search capability and optionally specialist agent recipe, not running processes; tenant-private details remain private.

## Other demonstration scenarios
- EV batteries: chemistry, cost/kWh, supply chain, charging, manufacturing; emphasize cell versus pack metric and commercialization versus laboratory benchmarks.
- Recycling: first request may require new domain mold and new waste-flow/statistics/processing patents connectors.
- Agriculture: link FAOSTAT, weather, academic patents and agronomic time series; distinguish causal effects.
- Geopolitics: event data vs verified state actions, competing narratives, no invented probabilities.
- Cross-domain: battery-powered irrigation may compose energy, agricultural and AI engines **without creating permanent mold**.

## Customer experience principles
Arabic and English capable, source transparency, clear intermediate states, progress that distinguishes discovered/tested/approved, downloadable evidence and report assets, no premature 'done' banners. Status tasks have recoverability and resumable checkpoints.
