# MANARA Functional Capability Catalog

> **Purpose:** A brutally-honest, capability-by-capability catalog of every
> functional claim the MANARA backend makes, classified per the owner's
> 7-tier verification scheme. Companion file to `API_REFERENCE.md`.
> **Code source:** `backend/src/manara/`
> **Doc status:** Generated by reading the actual code on 2026-10-19.
> **Test totals:** 320 test functions across 18 test files under `backend/tests/`.

---

## 1. The 7-Tier Classification Scheme

Each capability below is tagged with exactly one of:

| Tier | Meaning |
|---|---|
| `IMPLEMENTED_AND_VERIFIED` | Code complete AND end-to-end tests pass (incl. live network/DB calls where applicable). |
| `IMPLEMENTED_NOT_LIVE_TESTED` | Code complete, unit tests pass, but NO live API/network/LLM test was exercised in the sandbox. |
| `PARTIALLY_IMPLEMENTED` | Some aspects work; others don't (specifically called out per capability). |
| `CONTRACT_OR_CATALOG_ONLY` | Type/contract or catalog entry exists but no runtime behavior is wired. |
| `MOCK_ONLY` | Only the mock provider / seed card path works; the real backend is stubbed. |
| `NOT_IMPLEMENTED` | Declared in spec or router docstring but absent from code. |
| `BLOCKED_BY_ENVIRONMENT` | Code present but blocked (needs Docker, API key, browser, Postgres+pgvector, etc.). |

When a capability spans multiple tiers (e.g. "works for the mock path, blocked
for the live path"), the **lower** tier wins on the headline and the gap is
explained in the "Honest limitation" field.

## 5. Foundry Layer (G02)

### 5.1 SSRF Protection (validate_url + SafeHttpClient)

| Field | Value |
|---|---|
| **Capability name** | Hardened HTTP egress with allowlist, private-IP blocking, redirect rejection, content-type verification |
| **Modules** | `src/manara/foundry/safe_http.py` (`validate_url`, `SafeHttpClient`, `SsrfViolation`, `FoundryRequestConfig`, `PRIVATE_NETWORK_PATTERNS`). |
| **Description** | `validate_url(url, allowed_hosts)` enforces 6 rules: (1) scheme must be `https` by default; (2) host must be in `allowed_hosts`; (3) DNS resolution must not return private/loopback/link-local/metadata IPs; (4) no embedded userinfo; (5) no fragment; (6) length > 0. `SafeHttpClient.get()` wraps `httpx` with a 5 MB response cap, NO automatic redirects (caller must explicitly invoke `follow_redirect()` which re-validates the target), and a hard `expected_content_types` check — content-type mismatch raises `SsrfViolation` (this is a BACKEND-VERIFICATION-01 hardening fix). |
| **Tests** | `backend/tests/test_foundry.py` (32); SSRF-specific cases verified there. |
| **Tier** | `IMPLEMENTED_AND_VERIFIED` |
| **Honest gap** | The client is intentionally minimal — no caching, no rate-limiting, no auth handling (those are the connector's responsibility). The 5 MB cap is hard-coded; large responses (e.g. OpenAlex `/works?per_page=200` with full authorships) may exceed it. |
| **UI team needs** | SSRF violations surface as `SsrfViolation` exceptions, caught by the Foundry service and recorded as `error="ssrf_violation:<rule>"` in `FoundryCallRecord.error`. The UI should display these errors verbatim — they are diagnostic, not user-facing faults. |
