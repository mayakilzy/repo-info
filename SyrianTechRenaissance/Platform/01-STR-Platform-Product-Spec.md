# STR Platform v1.0 — المواصفات الوظيفية والمؤسسية

**التاريخ:** 2026-10-17  
**الحالة:** نطاق وظيفي متفق عليه في الحوار؛ تفاصيل التقنية في وثائق منفصلة  
**المنتج الحالي:** المنصة المؤسسية STR Platform فقط

## 1. الهوية والغاية

الاسم: **Syrian Tech Renaissance (STR) — النهضة التقنية السورية**. الشعار المؤسسي المتفق عليه: **«النهضة التقنية السورية مبادرة سورية المنشأ والرسالة، عالمية الانفتاح والتعاون»**.

مبادرة تقنية مستقلة سياسياً وحزبياً ودينياً وطائفياً، منفتحة على المشاركة المهنية من جميع الجنسيات والخلفيات. يمنع استخدام المنصة للدعاية أو التحريض أو المنازعات السياسية والدينية والطائفية خارج الحاجة المهنية المباشرة إلى متطلبات قانونية أو سياسات مرتبطة بالمشروع. يُحكم التعاون بالخبرة والعمل والنزاهة والاحترام وعدم التمييز، وليس بالعلاقات أو الولاءات.

الهدف تحويل المهارات والخبرات المتناثرة إلى فرق عمل منتجة، ومشاريع وعقود وشراكات وعوائد قابلة للاستدامة، مع إعادة استثمار الفائض المتاح في التعليم والتنمية السورية وفق حوكمة قانونية ومالية تُعتمد لاحقاً. المنصة ليست منتدى دردشة ولا مؤسسة سياسية ولا مصنع التطبيقات نفسه.

## 2. النطاق المرحلي الصارم

**الآن:** البوابة العامة؛ التسجيل والهوية؛ الملفات المهنية ودليل المواهب؛ طلبات المشاريع والاعتماد؛ الفرق المؤسسية؛ الفرص والمشاركة؛ إدارة المشاريع الأساسية؛ المساهمات والحقوق؛ الشراكات؛ التواصل المرتبط بالعمل؛ الحوكمة والإدارة؛ تقارير وقياس أثر مستند إلى الأدلة؛ دليل الأدوات وبنية تكاملات حقيقية قابلة للاختبار.

**لاحقاً كمشاريع منفصلة:** STR Academy (ورش العمل الهندسي الجماعي والتعلم التطبيقي)، وSTR Engineering Ecosystem (جرد دكة الاحتياط وتوظيف أدواتها، وورشة القدرات الاثنتي عشرة السابقة). كل منظومة مستقلة الشيفرة والتشغيل عند الاقتضاء وتتكامل مع STR؛ لا تعيد المنصة بناء هذه الأنظمة.

**غير داخل v1:** نظام محاسبة أو رواتب/عقود قانونية مؤتمتة كاملة؛ بناء أدوات AgentCraft؛ تكاملات إنتاجية مع n8n/Make/Airtable/Google Drive/Genesis/Sentinel/APP Tester؛ تشغيل شيفرة الأعضاء؛ مجتمع ترفيهي مفتوح أو دردشة عامة بلا سياق عمل.

## 3. أعضاء المنصة والهوية

- تسجيل مفتوح بالبريد وكلمة مرور، **مع تحقق من البريد** قبل تفعيل المشاركة ذات الأثر المؤسسي.
- **Continue with Google** عبر OpenID Connect. ربط الهوية بمعرّف Google الثابت `sub` وليس البريد فقط؛ لا ربط تلقائي غير موثوق بحساب قائم؛ عملية ربط صريحة مع إعادة إثبات ملكية الحساب.
- ملف مهني: خبرات، تخصصات، مهارات، لغات، أعمال سابقة، توافر للمشاركة، معلومات الاتصال وإعدادات ظهورها. إثبات الخبرة أو التحقق المهني مسار مستقل لا يعني أن المستخدم موثوق تلقائياً.
- حساب واحد للشخص مع أدوار مختلفة حسب نطاق المؤسسة/المشروع/الفريق. لا يكفي إخفاء الأزرار لمنع الوصول.

## 4. قرار حوكمة الفرق المعتمد STR-GOV-TEAM-01

**أُلغي مفهوم تأسيس فرق تشغيلية بحرية بمجرد التسجيل.** يستطيع العضو المؤهل **تقديم مقترح مشروع**، والتشاور حول فكرته بدون موارد هندسية؛ لكن لا ينشأ فريق تشغيلي أو مساحة عمل ذات موارد أو تفويض مؤسسي حتى:
1. تُقدَّم **وثيقة مشروع** توضّح المشكلة والهدف والنطاق والمستفيدين والمخرجات والمهارات والمتطلبات ومعمارية مناسبة والموارد والمخاطر والحقوق ومعايير القبول.
2. تراجع الجهة المخولة توافقها مع رسالة STR والأمن والموارد والحقوق.
3. تُعتمد الوثيقة ويُعيّن **قائد فريق** و**مشرف مؤسسي STR Steward** لكل فريق.
4. تُحدد صلاحيات الفريق وحدود موارده وأدواته ومدة التفويض.
5. يخضع التغيير الجوهري في المشروع والموارد لمراجعة جديدة، دون إلزام الإدارة بالموافقة على كل commit أو قرار هندسي يومي.

يمكن للمبتدئ تقديم تصور غير مكتمل؛ يساعده مراجع في إعداد المخطط قبل الموافقة التشغيلية. المشرف الإداري مسؤول عن الإشراف والتصعيد والمراجعة وليس قائد العمل اليومي. الموافقة البشرية **لا تغني** عن العزل ومنع تشغيل كود غير موثوق والوصول المحدود القابل للإلغاء وتسجيل الأدلة. لا يجوز لفريق غير معتمد تمثيل المؤسسة أو الوصول إلى أدواتها.

## 5. مجالات الوظائف — رموز P01–P12 خاصة بالمنصة لا بتطبيقات دكة الاحتياط

| رمز | المجال | القيمة / مسار القبول الأساسي |
|---|---|---|
| P01 | موقع المؤسسة العام | فهم الرسالة، التقديم، الفرص العامة، إيضاح الخدمات المستقبلية غير المشغلة |
| P02 | الهوية والعضوية | التسجيل البريدي والتحقق وGoogle واستعادة الحساب والصلاحيات |
| P03 | دليل المواهب | ملفات مهنية، بحث وتصنيف، خصوصية وإثبات الخبرة دون ادعاء التحقق آلياً |
| P04 | الفرق المعتمدة | فرق ناتجة عن مشروع معتمد، قائد ومشرف ودعوات وحالة تفويض |
| P05 | الفرص | مسودة، مراجعة، نشر، طلبات وترشيح وقبول/رفض/انسحاب |
| P06 | المشاريع | مبادرة/وثيقة، اعتماد، مراحل، مهام، تسليم ومراجعة ومخرجات |
| P07 | الشراكات | جهات وممثلون وطلبات وحالات تعاون وصلاحيات |
| P08 | المساهمات والحقوق | توثيق من ساهم وماذا قُبل ورابط الاتفاق، دون نقل ملكية تلقائي |
| P09 | التواصل | إشعارات ونقاش سياقي للمشاريع والفرق، لا منتدى حر بديل |

## 6. دورات العمل المقبولة

- **العضوية:** زائر → تسجيل → تحقق → ملف مهني → استكشاف فرصة → تقديم → متابعة.
- **المقترح والفريق:** عضو → مقترح → استكمال Charter/Blueprint → مراجعة/استيضاح → موافقة أو رفض موثق → قائد + Steward → منح الأذونات → الدعوات → تشغيل محدود النطاق.
- **الفرصة التجارية:** فرصة مسودة → مراجعة → إعلان → اهتمام/طلبات → اعتماد مشروع أو إغلاق؛ لا تتداخل الموافقة على الفرصة مع تفويض الإنفاق.
- **المشروع:** تحضير → اعتماد → تكليف مهام → تسليم → مراجعة/إعادة → قبول → توثيق مساهمات ونتائج.
- **الشراكة:** استفسار → مراجعة → تفاوض → قرار → وثائق وصلاحيات.
- **الحقوق:** وصف مساهمة → أدلة → مراجعة/اعتماد → إسناد لصاحبها ومرجع الاتفاق؛ أي تحويل ملكية يحتاج اتفاقاً صريحاً منفصلاً.

## 7. المبادئ التقنية والتشغيلية المعتمدة وظيفياً

- دعم العربية RTL والإنجليزية وتصميم متجاوب وإتاحة وصول مناسبة.
- خيارات المستخدم والخصوصية والبيانات الحساسة محكومة بالتصريح الصريح.
- فصل المنصة عن الأكاديمية والمنظومة الهندسية من المصدر وقواعد البيانات والمنشورات.
- خدمات الأدوات في مواقعها/أنظمتها الخاصة. الوصول عبر موصلات ومفاتيح مفوضة لا يساوي الوصول لشيفرتها أو نقل حقوقها.
- Integration Core يجهز ويُختبر برمجياً في v1؛ **لا تكامل وهمي ظاهر للمستخدم**.
- اختبارات متصفح فعلية بأدوار متعددة ومسارات إيجابية وسلبية، بجانب unit/integration/security tests.
- تنظيم العمل وثوابت المراجعة المطلوبة قبل النشر.

## 8. معايير قبول v1 الحاسمة

A01 تسجيل بريد + تحقق + تسجيل Google فعلي بأمان وربط حساب آمن.  
A02 عضو بلا مشروع معتمد **لا ينشئ فريقاً تشغيلياً** ولا يحصل على موارد/أدوات.  
A03 قبول مشروع Charter يؤدي إلى فريق وقائد وSteward ونطاق تفويض؛ رفضه لا يفتح أي موارد.  
A04 عزل فرق ومشاريع مختلفين: محاولة قراءة/تعديل عابرة تُرفض على الخادم.  
A05 إكمال فرص وتقديمات ومراجعات وشراكات وسجل مساهمات مع أدلة وحقوق.  
A06 Integration Mock Connector ينجح في تسجيل مزود وربط مقيّد وتشغيل مهمة وتتبعها واستقبال نتيجتها وإبطال الربط، مع اختبارات تزوير/تكرار/فشل.  
A07 واجهات عربية/إنجليزية، RTL والهاتف، لا أزرار شكلية.  
A08 اختبارات سلبية للأمن والصلاحيات، وسجلات تدقيق للأحداث الحساسة.  
A09 نشر staging موثق واستعادة نسخة احتياطية مجربة.  
A10 اختبارات Browser E2E حقيقية بأدوار متعددة وأدلة لقطات/مسارات وحالة واضحة لكل مسار.

## 9. ما لم نعتمده تفصيلياً بعد

الشكل القانوني، التعويضات والنسب، شروط العقد القانوني، مؤشرات كمية نهائية، ألوان التصميم، وسقف موارد التشغيل التفصيلي؛ تحسم هذه في قرارات مستقلة لا بتخمين من المطور. المعمارية التقنية المحددة مقترح مهني يجب إثبات ملاءمته في G01.
