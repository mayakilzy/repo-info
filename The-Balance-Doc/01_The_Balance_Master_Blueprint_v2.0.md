# 1. رسالة الميزان

**السؤال الأعلى:** «كيف أبني دولة متحضرة وقادرة على التقدم والاستمرار؟»

الميزان منصة ذكاء دولة مبنية على الأدلة، موجّهة أساساً للحكومات الشرعية المخولة، تساعدها على فهم الحالة الفعلية للدولة، وتصميم استراتيجيات ومشروعات إصلاح مترابطة، ومرافقة التنفيذ، وقياس النتائج وتفسيرها باستقلال، واقتراح مراجعات وتحسينات، وحماية ذاكرة الدولة الاستراتيجية عبر تغير الحكومات. لا يحل النموذج محل مؤسسات الدولة أو المواطنين ولا يستبدل العمليات السياسية والدستورية.

المنتج **عالمي** بــ Universal Core + Country Pack؛ سوريا أول دراسة حالة معمقة لا تعريف للمنتج ولا معيار جاهز لجميع الدول. الحكومة عميل العمل الأول؛ تضاف بوابات بحث/نشر عامة لا تكشف بيانات غير منشورة ولا تخلط الادعاء السياسي بالحقيقة.

## 1.1 حدود ما يدعيه المنتج
- **يفعل:** تنظيم أدلة قابلة للفحص، مقارنة بدائل، حساب مؤشرات معرفة المصدر، تحليل تبعيات البرامج، كشف فجوات التنفيذ، وإنتاج مذكرات توصية مشروطة.
- **لا يدعي:** معرفة موضوعية كاملة لمفهوم «الدولة الجيدة»، أو توقع المستقبل يقيناً، أو إثبات السببية بمجرد الارتباط، أو منح حكومة «درجة أخلاقية»، أو ضمان نجاح خطة تنموية، أو اتخاذ قرارات سيادية.
- **لا يفعّل:** مراقبة الأفراد/التنميط السياسي أو الأمني للمواطنين، أتمتة العقاب، أو أدوات مساس بالحقوق؛ أي وصول لبيانات خاصة مشروط بحدود الغرض والقانون والحاجة.

## 1.2 المستفيدون
1. مجلس الوزراء/مكاتب الاستراتيجية: خطة الدولة، الأولويات والمراجعة.
2. الوزارات والهيئات والمحليات: برامج إصلاح قطاعية قابلة للتتبع.
3. وحدات التقييم والتدقيق المستقلة: نتائج ومؤشرات وأدلة مضادة.
4. الباحثون والجمهور: نتائج منشورة، منهجيات، تحفظات وعدم اليقين؛ **ليس** وصولاً تلقائياً إلى الخطط الحكومية الداخلية.

## 1.3 معايير نجاح القيمة
قدرة الحكومة على: (أ) الحصول على خط أساس موثق، (ب) مقارنة عدة استراتيجيات، (ج) ربط كل مشروع بموارده ومسؤولياته ومؤشراته، (د) رؤية الفرق بين المخطط والمرصود، (هـ) مراجعة الخيارات بناء على أدلة جديدة، (و) تسليم دورة التعلم التالية دون فقدان السبب والسياق. النجاح البرمجي شرط لازم لكنه غير كاف؛ أثر المنظومة على قرارات فعلية يحتاج تقويماً ميدانياً منفصلاً.

# 2. المبادئ العلمية والمؤسسية

| المبدأ | تطبيق ملزم |
|---|---|
| Evidence before conclusion | كل استنتاج محدد مرتبط بسلسلة أدلة ومصدر وتاريخ وطريقة معالجة |
| Unknown is a valid result | النظام يمتنع عن القياس أو الاستنتاج عند نقص البيانات |
| Multi-source & independence | لا تُحسب النسخ المتطابقة/المقتبسة كمصادر مستقلة |
| Counter-evidence | طلب بحث مضاد موثق للادعاءات عالية الأثر |
| Separating levels | الفصل بين الادعاء والملاحظة والتفسير والارتباط والسببية والتوصية |
| State Vector | أبعاد منفصلة للوضع والاتجاه والجودة والإنصاف والتنفيذ ولا رقم سحري واحد |
| Uncertainty calibration | لا عرض لنسبة ثقة مصطنعة؛ أسباب عدم اليقين، نطاقات موثقة حين تصلح |
| Temporal validity | تاريخ الواقع وتاريخ الاكتشاف/التسجيل وإصدارات التصحيح |
| Transferability | لا نقل آلي لـ«نموذج سنغافورة»؛ تقارن الشروط والمؤسسات والقدرات |
| Human sovereignty | لا إقرار قانون أو موازنة أو صرف أو إلغاء برنامج من الوكلاء |
| Continuity without lock-in | حفظ المعرفة دون فرض استمرار سياسة قديمة أو مصادرة خيارات الحكومة الجديدة |
| Reproducibility | سجل مصدر ونموذج ونسخة أداة وبيانات مدخلة ومخرج قابل لإعادة الحساب عند الإمكان |
| Security & privacy | أصغر امتياز، عزل مستأجر، تفويض، تدقيق وعدم نشر الافتراضات الحساسة |

نُعامل الكتب النظرية كفرضيات وآليات قابلة للاختبار لا كأحكام «خضراء/حمراء». مصادر البيانات الدولية تعطي Benchmarks مع قيودها المنهجية، وليست بديل تشخيص محلي. أمثلة المصادر الواردة في السجلات: WGI، V-Dem، Open Budget Survey، World Bank Enterprise Surveys، World Bank Data، IMF، ILO، OpenAlex، Semantic Scholar، GDELT، Common Crawl، وبيانات حكومية ومحلية وأقمار صناعية؛ كل تكامل يحتاج تحققاً حديثاً من الترخيص وإتاحة API ومعدل تحديثه قبل التنفيذ.

# 3. القدرة الحكومية: الرحلات الثلاث والوظائف العابرة

## 3.1 BUILD — State Builder / بناء الدولة
**مدخلات:** Country Pack، أهداف تصوغها الجهة المخولة، حدود الموارد والزمن، خط أساس، سيناريوهات وتفاوت إقليمي.  
**عملية:** تشخيص → أهداف قابلة للملاحظة → فجوات → خيارات سياسة مؤيدة ومعارضة → تحليل قدرة التنفيذ → رسم التبعيات بين القطاعات → ترتيب الأولويات → تخصيص موارد وموازنة تقديرية → تصميم البرامج والمسؤوليات → توقيت مرحلي → مقاييس نجاح وفشل → مراجعة وإقرار بشري.  
**مخرجات:** National Vision، Strategy Version، Reform Portfolio، Program/Project Plans، Risk Register، Assumptions، Evidence Dossier، Decision Brief.  
**نطاق:** الوزارات والهيئات والمحليات، المالية العامة، الاقتصاد، الصحة، التعليم، الطاقة، المياه، الزراعة، البيئة، القانون، الإدارة، البنى الأساسية، المجتمع؛ لا يفرض نموذج حكم موحداً.

## 3.2 OBSERVE — State Observatory / الرصد والتقييم
**مدخلات:** المؤشرات والمصادر المرصودة، قرارات حكومة مثبتة المصادر، خطط معتمدة، تنفيذ موثق، أرقام مستقلة.  
**عملية:** مراجعة جودة المصدر → تحديث خط الأساس → حساب متجهات المؤشرات → مقارنة بالقيم المرجعية والأهداف → اكتشاف انحراف → اختبار الأدلة المعارضة/الافتراضات البديلة → وصف مستوى الإسناد السببي الممكن → إصدار تقرير مستقل وإنذار مبرر.  
**مخرجات:** State Snapshot، Indicator Series، Variance Report، Evidence Case، Warning Case، Independent Assessment.  
**الحاجز:** لا يغير OBSERVE نتيجته ليلائم خطة BUILD؛ ويمكنه أن يخالف توصية المستشار.

## 3.3 REFORM — Targeted Reform / الإصلاح المحدد
**مدخلات:** هدف قطاعي، أزمة موضعية، ملاحظة من Observatory، طلب وزارة أو بلدية، تقييدات محلية.  
**عملية:** نطاق المشكلة → تشخيص متخصص → استدعاء خبراء المياه/الطاقة/المالية/القانون حسب الحاجة → بدائل وآثار جانبية → خطة تنفيذ واختبار أثر → اعتماد بشري.  
**مخرجات:** Targeted Reform Proposal، Dependency Impacts، Implementation Tasks، Measurement Plan، Change Request قابل للربط باستراتيجية وطنية قائمة.  
**القاعدة:** لا يتطلب الإصلاح الجزئي إعادة بناء دولة كاملة.

## 3.4 IMPLEMENT — طبقة المتابعة التشغيلية
ليست بالضرورة بوابة أو محركاً خامساً. تعني إدارة وضع البرامج: مالك الجهة، خطة العمل، الموارد المرصودة، المواعيد، الدليل على التنفيذ، الفوارق، إجراءات التصحيح والاعتمادات. لا يعني تفعيل إجراء سيادي في نظام مالي/إداري دون تفويض.

## 3.5 Development Advisor — المستشار التطويري
قدرة عابرة للرحلات الثلاث: يولد بدائل متعددة، شروط نجاح، تحليل مخاطر، تقديرات تكلفة حين تتوفر بيانات، الآثار على القطاعات، الافتراضات والأدلة المعارضة، ثم يقدم **توصية مشروطة**. لا يمتلك سلطة تغيير خطة معتمدة أو إلغاء مشروع. يمكن تنفيذه كسير عمل تقوده المنظومة لا كوكيل دائم إضافي.

## 3.6 National Strategic Continuity — الاستمرارية الوطنية
الكنز طويل العمر: حفظ الرؤية والأهداف والإصدارات وأسباب القرارات والالتزامات والتكاليف والنتائج والدروس. عند تغير الوزراء أو الحكومات ينتج **Government Handover Dossier** يوضح ما اكتمل، وما تعثر، وما يستوجب الاستمرار قانونياً، وما يمكن تعديله، وآثار الاستمرار/التعديل/الإلغاء. لا يخلط ذاكرة الدولة بتجميد سياسة سابقة.

# 4. خريطة نموذج الدولة والمعرفة

## 4.1 State Ontology (عامة وقابلة للتخصيص)
Country، AdministrativeUnit، Institution، Ministry، LegalMandate، PopulationGroup *aggregated*، Sector، Policy، Decision، Strategy، Program، Project، BudgetLine، Resource، Asset، Indicator، Observation، Outcome، Risk، Evidence، Source، ResearchStudy، HistoricalCase، ActorRole، Approval، Event، Relationship. لكل كائن معرف ثابت، مصدر، مالك، صلاحية رؤية، تاريخ ونطاق جغرافي وإصدار.

## 4.2 Knowledge Core
ثلاث طبقات لا تُخلط: (أ) نظرية وآليات سياسات؛ (ب) نتائج تجريبية ودراسات حالات نجاح/إخفاق وفترات محددة؛ (ج) مؤشرات ومعايير وبيانات زمنية. تُحفظ النصوص بالقدر المرخص؛ النص الكامل ليس شرطاً لجمع المعرفة البنيوية. يكون المخزن المتجهي استرجاعاً دلالياً فقط، وليس القاضي أو مصدر الحقيقة.

## 4.3 Country Pack
`country_id`, الاسم واللغات، مستويات الإدارة، المؤسسات ومسمياتها، مراجع قانونية، موصلات، قطاع اقتصادي، عملة ووحدات، تاريخ القطاعات، القيود والحوكمة، مخطط جودة البيانات. لا يُزرع علمياً حكم جاهز على نظام سياسي أو مجتمع. سوريا هي الدراسة الأولى لحالة Low-Observability مع الاحتفاظ بأهلية أي Country Pack ثانٍ.

## 4.4 التغطية الموضوعية
الاقتصاد الكلي؛ المالية العامة؛ النقد والتمويل؛ الاستثمار والأعمال؛ الحكم والمؤسسات؛ القضاء وسيادة القانون؛ مخاطر الفساد والاستيلاء المؤسسي؛ الإدارة العامة؛ الصحة؛ التعليم؛ الحماية الاجتماعية؛ العمل والمهارات؛ الطاقة والمياه والبنية التحتية؛ الزراعة والغذاء والموارد؛ التجارة والعلاقات الاقتصادية؛ المناخ والبيئة والجغرافيا؛ المجتمع والخدمات؛ الصدمات والروابط الخارجية. تُحدد بطاقات الخبراء والقياسات لكل نطاق دون افتراض أن حدود الوزارات تطابقها.

# 5. Evidence Fabric / المسار العلمي للادعاء

المسار: **Discovery → Acquisition → Rights/Source Check → Extraction → Claim Atomization → Independent Corroboration → Counter-Evidence → Indicator Link → Temporal Link → Causal Caution → Review → Published Evidence Case**.

## 5.1 Evidence Object — الحد الأدنى التعاقدي
```json
{
  "evidence_id":"uuid", "country_id":"string", "source_id":"string",
  "source_uri":"string", "source_kind":"official|academic|survey|media|field|other",
  "retrieved_at":"ISO-8601", "valid_at":"ISO-8601|null",
  "content_hash":"sha256", "license_status":"allowed|metadata_only|review_required",
  "claim_text":"string", "claim_type":"reported|observed|interpreted",
  "support_stance":"supports|contradicts|neutral|uncertain",
  "independence_group":"string|null", "quality_notes":[],
  "verification_status":"unverified|corroborated|verified|disputed",
  "visibility":"public|tenant_private|restricted", "schema_version":"1"
}
```
هذه **مسودة عقد v0** لا مخطط قاعدة بيانات نهائي. لا يجوز ترقية المحتوى المسرب إلى «حقيقة» تلقائياً؛ لا نستخدم عدد الروابط بدلاً من استقلالية المعلومات، ولا نعرض توثيقاً غير حاصل فعلاً.

## 5.2 Indicator Registry
لكل مؤشر: التعريف، الصيغة ووحدة القياس، الاتجاه المفضل ولماذا، المستويات الجغرافية، مصدر/سلسلة، التغطية، التواتر، تاريخ المنهجية، قيود القياس، طريقة حساب عدم اليقين، ومن يستخدمه. فصل القيمة الأساسية عن اتجاه تغيرها وعن هدف الحكومة وعن جودة بياناتها.

## 5.3 Evidence Case / Research Dossier
سؤال محدد + ادعاءات قابلة للفحص + أدلة مؤيدة + أدلة معارضة + اعتماد المصادر + مؤشرات + ملاحظات سببية + خلافات علمية + تفسير بديل + درجة يقين مناسبة أو «غير معروف» + سلسلة مراجعة وتوقيع نشر.

## 5.4 National Observability Modes
`FULL` للبيانات الموثوقة الواسعة؛ `PARTIAL` مع توضيح حدود التغطية؛ `LOW` مع حالات عدم المعرفة والاعتماد المتبادل والبحث البديل. نقص المنشورات الرسمية ليس دليلاً بذاته على فساد أو خلل.

# 6. سياسات واستراتيجيات قابلة للنسخ والتغيير دون فقد التاريخ

## 6.1 Strategy Contract v0
```json
{
  "strategy_id":"uuid", "country_id":"string", "version":1,
  "title":"string", "horizon_start":"YYYY", "horizon_end":"YYYY",
  "status":"draft|proposed|approved|active|amended|retired",
  "issuer_institution_id":"string", "owner_role_id":"string",
  "objective_ids":[], "program_ids":[], "indicator_ids":[],
  "constraints":[], "assumptions":[], "evidence_case_ids":[],
  "created_at":"ISO-8601", "supersedes_version":null,
  "approval_record_id":null, "change_reason":null
}
```

لا تعدل الخطة المعتمدة في مكانها؛ ينشأ إصدار جديد مع Diff والتبرير ومراجع الأدلة. كل برنامج مرتبط بتكلفة متوقعة ومصدر تمويل وتبعيات ومسؤول ومخاطر وأحداث تنفيذ فعلية/مزعومة ومصادرها.

## 6.2 Strategy Change Impact Assessment
يحسب التغيير على الأقل: الالتزامات القائمة، التكاليف الغارقة (لا تُحتسب معياراً منفرداً للاستمرار)، آثار تعطيل الخدمات، الارتباط بين البرامج، عبء التمويل، المستفيدين، الزمن، ضياع المعرفة، البدائل، عدم اليقين وخطة الانتقال. حزم الانتقال لا تكشف أسرار الحكومة السابقة لمستفيد غير مخول.

## 6.3 Institutional memory and handover
Event log مستمر غير قابل للمحو العادي، snapshot قابل للاستعادة، مؤشر مصدر/قرار/اعتماد/إصدار لكل واقعة. تغيير الحكومة لا يغير التاريخ؛ يمكنها نشر تعليق تصحيحي أو تعديل السياسة بإجراءات معلنة. نجاح اختبار T4 مشروط بإعادة بناء سبب القرار وليس استرجاع النص النهائي فقط.

# 7. المحركات الأربعة وحدودها

| Engine | مسؤولية كتابة الحقيقة التشغيلية | علاقة بالمكونات الأخرى |
|---|---|---|
| State Builder | مسودات استراتيجيات وبرامج وإصداراتها؛ الموافقة البشرية وحدها تجعلها معتمدة | يستهلك Baseline وEvidence، ويرسل أهداف التنفيذ |
| State Observatory | ملاحظات ومؤشرات وتقارير تقييم موثقة ولا يغير الاستراتيجية | يرصد النتائج والخلافات ويرسل Signal مستقل |
| Targeted Reform | طلبات إصلاح وبدائل وتبعيات ومقترحات تعديل | يستهلك Signal ويقترح Change Request إلى Builder |
| Strategic Continuity | تاريخ الإصدارات والتغيرات والحزم الانتقالية والدروس | يربط كل رحلة عبر الزمن ولا يفرض الاستمرار |

**قاعدة واحدة:** الاستراتيجية ليست الملاحظة، والملاحظة ليست القرار، والتوصية ليست الموافقة، والموافقة ليست إثبات التنفيذ.

# 8. Balance Master والسرب والخبراء

## 8.1 Master Orchestrator
يفهم الطلب، يصنفه، يختار المكونات والقدرات من Capability Registry، ينشئ مهمة ذات ID وتتبعات، يوزع العمل، يتعامل مع فشل الأدوات واستئناف العمل، يجمع المخرجات، ويطلب نقداً مستقلاً عند اللزوم. **ليس خبيراً أعلى يحتكر الاستنتاج ولا جهة اعتماد حكومي**.

## 8.2 Domain Expert Protocol (مسودة)
`expert_id, version, domains, country_coverage, accepted_input_schema, output_schema, tools, scopes, evidence_requirements, evaluations, limits, status`. طلب الخدمة يحمل `task_id`, `country_id`, `problem_statement`, `constraints`, `requested_output`, `evidence_refs`, `deadline_optional`, `caller_permissions`. الرد يحتوي `findings`, `alternatives`, `assumptions`, `counter_evidence`, `references`, `uncertainty`, `handoff_recommendations`, `execution_trace_id`.

## 8.3 التعاون والنقد
باحث أدلة، خبير قطاعي، محلل تبعيات، خبير تكلفة، ناقد علمي، مراجع حقوق/سلامة، مدقق تنفيذ. يمكن استخدام تفاوض A2A متعدد الأدوار، لكن لا يجوز اعتبار «قرار الأغلبية بين الوكلاء» تحكيماً علمياً، ولا يصبح حكم Master حقيقة رسمية.

## 8.4 إعادة استخدام Swarm Engine
الملف المرجعي يصف Layers للتنسيق وWebMCP/RAG/A2A/Sub-Agent Factory، لكنه يتضمن مكوّنات Mock وتجارب UI وتأخيرات محاكية. نعيد استخدام **الأفكار والكود المُتحقق منه فقط** بعد تدقيق رخصة MIT المعلنة، واختبار codebase ومخرجات حقيقية؛ لا نعده محركاً إنتاجياً حكومياً بمجرد README. التوابع المعتمدة: بروتوكول مهمات ودورات حياة وأذونات وتتبعات دائمة ودعم Backends؛ لا تجعل تنفيذ العمل الحكومي في React browser ضرورة تقنية.

## 8.5 الأدوات وتنفيذ الأفعال
تصنيف الأدوات `read_only`, `draft_write`, `approved_action`, `prohibited`. أدوات التحليل يمكن أن تعمل تلقائياً داخل صلاحيات محددة؛ التحديث الرسمي والإنفاق والنشر المحمي يحتاجان تفويضاً سياقياً ومراجعة بشرية وسجل موافقة. رفض النداء غير المصرح به يجب أن يكون في طبقة الخادم وليس prompt فقط.

# 9. التخزين والتشغيل والبنية المقترحة

## 9.1 التصميم المنطقي أولاً
Modular platform ضمن مستودع رئيسي واحد مبدئياً، Backend API وعامل مهام وخدمات معرفة وأدلة وواجهات متعددة، دون فرض microservices أو قاعدة منفصلة لكل خبير. يمكن PostgreSQL + JSONB + pgvector كبداية؛ مخزن كائنات للوثائق المرخصة؛ graph relationships من نمذجة علائقية أو مخزن graph فقط عند إثبات فائدته؛ queue/workflow للتحليل الطويل إن احتاجته التجربة. كل خيار تقني **مرشح** حتى يُفحص ضد متطلبات 00.

## 9.2 الحدود البنيوية
```
Government/Public UI → API/BFF (Auth/Permissions)
       → Balance Master / Task Orchestration
       → BUILD | OBSERVE | REFORM | CONTINUITY
       → Common Evidence/Knowledge/Country/Indicator/Registry
       → Data Stores + Adapters + Append-only Audits
```
واجهات القراءة العامة لا تختلط ببيانات المستأجر الحكومية الداخلية؛ Country Model العالمي لا يعني نسخ البيانات السرية بين الدول. لا تستدعي التطبيقات ملف Python مباشرة من GitHub كخدمة؛ الأدوات تنشر عبر عقود API/SDK versioned.

## 9.3 متطلبات وظيفية غير اختيارية
Persistent tasks، idempotency، versioned migrations، data lineage، lifecycle statuses، negative test authorization، reconciliation for external data، feature toggles لأدوات غير موثوقة، backup/restore drills، observability (logs/metrics/traces) مع حذف أسرار وسلاسل بيانات حساسة، API versioning، test fixtures، CI.

# 10. الأمان والحوكمة والبحث المستقل

- **Threat model:** إساءة استخدام بيانات حكومة، إدخال مصادر مفبركة، تسميم RAG، حقن أوامر داخل نصوص مسترجعة، تسريب مفاتيح، تقمص أدوار، ترقية أوامر غير مخولة، تلاعب بنتائج المؤشرات، إسقاط نسب السببية، وتلوث نتائج البحث التجريبي المنشورة.
- **RBAC + ABAC:** صلاحيات على country/tenant/object/action/data_classification وrole، مدعومة بخادم API وDB policy حيث يلزم.
- **مصادر خارجية غير موثوقة:** النص المستخرج بيانات لا تعليمات؛ منع SSRF والنطاقات الداخلية؛ حجم/نوع المحتوى؛ استبعاد روابط تنزيل غير آمنة.
- **الاستقلال:** جهة تقييم يمكنها تسجيل اعتراضات على الخطة؛ فصل الصياغة عن المراجعة والنشر؛ تدقيق التعديلات وسبب قبول الأدلة أو رفضها.
- **الحماية والحقوق:** Data minimization، سياسة احتفاظ وحذف منظمة، ضوابط نشر تجميعية، لا تتبع فردي حساس أو عقاب آلي، حقوق نشر وترخيص؛ مصادر التسريب توسم وتفصل عن «متحقق» حتى يقوم إثبات مستقل مناسب.
- **مدخلات المواطن:** جمع اختياري محمي أو بيانات تجميعية، وليست بوابة تجسس. المشاعر العامة مؤشر قبول اجتماعي، لا إثبات فشل سياسة.

# 11. التقييم العلمي لا التقني فقط

## 11.1 اختبارات التحقق
- وضع سؤال فيه بيانات ناقصة: يجب قول «لا نعرف» وعدم اختلاق قيمة.
- نتائج متناقضة: عرض الخلاف مع قوة المصدر وطبيعته لا انتخاب رواية.
- مصادر مكررة: عدم رفع الثقة لنسخ خبر واحد.
- سياسة جذابة لكن تعارضها دراسة معتبرة: ظهور المضاد ضمن التقرير.
- نموذج سببية ضعيف: وسم «ارتباط» وطلب دراسة أو تجنب استنتاج قاطع.
- سيناريو «What if»: الافتراضات واضحة، والمخرجات نطاقات/مسارات احتمالية وليست تنبؤات قطعية.
- إعادة التشغيل: حفظ المصدر والنسخة وما يلزم لحساب المؤشر نفسه والتحقق من التغييرات.
- أثر الانتقال الحكومي: استعادة خطط قديمة وتمكين التعديل وفق صلاحيات مع حفظ السلسلة.

## 11.2 الاختبارات الأربع الأساسية
T1 حكومة جديدة تصمم استراتيجية متعددة القطاعات؛ T2 حكومة قائمة ترى نتائج الخطة والانحرافات؛ T3 إصلاح محدد بلا إعادة تخطيط كل الدولة؛ T4 حكومة تأتي بعد سبع سنوات وتستعيد الإرث المعرفي وتقارن الاستمرار والتعديل والإلغاء. إضافة T5: محاولة نشر/تعديل بلا صلاحية تُرفض مع تدقيق؛ T6: مهمة تنقطع ثم تستأنف بلا ازدواج؛ T7: مقارنة حالة دولية لا تنسخ سياسات خارج سياقها.

## 11.3 Seven-Year Simulation
تسريع الزمن بإدخال بيانات اصطناعية أو تاريخية مصنفة بوضوح؛ تشغيل خطة، ميزانيات، تنفيذ، صدمة، نقد ومراجعة، انتقال حكومة. هو **اختبار هندسي/منطقي** للاستمرارية وليس تجربة تثبت أثر السياسة في العالم الحقيقي.
